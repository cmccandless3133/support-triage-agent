# Larkspur Forms support-triage dataset

Synthetic evaluation data for a support-ticket triage agent. **Larkspur Forms** is a fictional online form and survey builder for small businesses. It has four plans: Free, Starter $19/mo, Pro $49/mo and Business $129/mo, and annual billing gets 2 months free. Every company, person, email address and domain in this dataset is invented. Emails use `example.com`/`.example` domains, and the company's own domain is `larkspur-forms.example`.

## Ticket schema

| Field | Type | Meaning |
|---|---|---|
| `id` | string | `T-001` … `T-120` |
| `subject`, `body` | string | Customer-written ticket. Bodies are 30–150 words. |
| `customer_plan` | enum | `Free` \| `Starter` \| `Pro` \| `Business` |
| `type` | enum | `routine`: answerable directly from the KB. `edge`: vague, typo-heavy, non-native English, very long, angry-but-answerable, multi-issue, or only partly covered by the KB. `risky`: must always go to a human. |
| `expected_queue` | enum | Topical queue: `billing` \| `account_access` \| `technical` \| `integrations` \| `product_howto`. It is always set, even when the ticket escalates. |
| `should_escalate` | bool | `true` if the agent must hand off to a human rather than resolve the ticket. |
| `escalation_reason` | enum \| null | `null` when `should_escalate` is false. Otherwise one of `refund_outside_policy`, `legal_threat`, `security_incident`, `privacy_request`, `chargeback`, `abusive`, `prompt_injection`, `account_takeover_risk`, `out_of_scope`, `angry_high_value`, `multi_issue_complex`, `no_kb_answer`. |
| `relevant_kb` | string[] | KB ids that hold the answer or the governing policy. Routine tickets list 1–2. `no_kb_answer` tickets and pure out-of-scope requests list `[]`. |

## Labelling conventions

- **Routine** tickets never escalate, and their answer can be checked against the cited article(s).
- **Edge** tickets escalate only when no article answers the question (`no_kb_answer`), or when resolving it needs account-specific investigation or coordinated changes across several areas (`multi_issue_complex`). If an edge ticket has several issues but each one is answered by the KB, it does not escalate.
- **Risky** tickets always escalate, even if part of the message is a legitimate how-to question (for example, a prompt injection wrapped around a real question).
- When a ticket fits more than one escalation reason, the label is the most severe or specific one. A refund demand that also threatens a lawyer is labelled `legal_threat`. One that threatens a chargeback is labelled `chargeback`.
- HIPAA/BAA questions are labelled `out_of_scope`. KB-024 states that Larkspur does not support HIPAA and that support must escalate these questions to the compliance team.
- A respondent who is not a Larkspur customer is recorded as `customer_plan: Free`, because the schema requires a plan value.

Counts above were generated by script from `tickets.jsonl`.
